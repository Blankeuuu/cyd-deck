# PROJEKT: ESP32 CYD PC Dock / Media Controller / Stream Deck

Chcę zbudować kompletny fizyczny dock do komputera oparty na:

**ESP32-2432S028R / Cheap Yellow Display / CYD 2.8"**

Urządzenie będzie stało poziomo pod monitorem i ma pełnić funkcję:

* nowoczesnego media playera,
* kontrolera głośności Windows,
* Stream Decka / panelu skrótów,
* monitora parametrów PC,
* w przyszłości także panelu Codexa, Home Assistant, OBS itd.

To ma być faktycznie używalne urządzenie, a nie Arduino demo.

Najważniejszą częścią urządzenia jest **ładny Media Player z prawdziwymi okładkami albumów**.

---

# 1. SPRZĘT

Płytka:

**ESP32-2432S028R — Cheap Yellow Display / CYD**

Parametry:

* klasyczny ESP32 / ESP32-D0WD-V3 / ESP32-WROOM
* dual-core do 240 MHz
* 4 MB Flash
* około 520 KB SRAM
* Wi-Fi
* Bluetooth
* ekran TFT 2,8"
* natywna rozdzielczość 240×320
* resistive touchscreen
* microSD
* RGB LED
* sterowanie podświetleniem
* brak PSRAM

## BARDZO WAŻNE

Urządzenie będzie fizycznie ustawione:

**LANDSCAPE**

Cały interfejs ma działać jako:

**320 × 240 px**

Nie projektuj żadnego głównego UI 240×320.

# 2. PINOUT CYD

Użyj następującego pinoutu jako bazowego dla ESP32-2432S028R.

## TFT

```cpp
#define TFT_MISO 12
#define TFT_MOSI 13
#define TFT_SCLK 14
#define TFT_CS   15
#define TFT_DC   2
#define TFT_BL   21
#define TFT_RST  -1
```

Display korzysta typowo z hardware SPI / HSPI.

GPIO21 steruje podświetleniem.

Backlight jest aktywny HIGH.

Nie używaj GPIO4 jako TFT reset bez wyraźnego potwierdzenia hardware, ponieważ GPIO4 jest używane przez RGB LED.

---

# 3. DISPLAY CONTROLLER

Oferta mojego konkretnego modułu podaje:

**ST7789 / ILI9341**

Natomiast typowy ESP32-2432S028R bardzo często używa ILI9341.

NIE zgaduj.

Przygotuj projekt tak, aby obsługiwał oba warianty.

Najlepiej przygotować dwa środowiska PlatformIO, np.:

```text
cyd28_ili9341
cyd28_st7789
```

Cała aplikacja powinna być wspólna.

Różnica ma znajdować się tylko w HAL/config display.

Najpierw przygotuj prosty diagnostic firmware pozwalający szybko określić prawidłowy sterownik.

Jeżeli ILI9341 działa poprawnie:

* właściwe kolory,
* brak przesunięcia obrazu,
* całe 320×240 dostępne,

użyj go jako docelowej konfiguracji.

---

# 4. TOUCH — XPT2046

Touchscreen jest rezystancyjny.

Kontroler:

**XPT2046**

Pinout:

```cpp
#define TOUCH_CLK   25
#define TOUCH_MOSI  32
#define TOUCH_MISO  39
#define TOUCH_CS    33
#define TOUCH_IRQ   36
```

Touch ma własne linie SPI.

UWAGA:

Chcemy jednocześnie korzystać z:

* TFT,
* touch,
* microSD.

Klasyczny ESP32 ma ograniczoną liczbę hardware SPI hostów.

Docelowa architektura powinna preferować:

```text
TFT    → hardware SPI
microSD → hardware SPI
Touch  → software SPI / bitbang
```

jeżeli dzięki temu unikniemy konfliktów magistrali.

Nie próbuj użyć trzech niezależnych hardware SPI hostów, których ESP32 fizycznie nie posiada.

Touch nie wymaga bardzo wysokiej przepustowości, dlatego software SPI jest dla niego akceptowalne.

---

# 5. MICROSD

Karta microSD będzie częścią docelowego urządzenia.

Pinout:

```cpp
#define SD_CS   5
#define SD_SCLK 18
#define SD_MISO 19
#define SD_MOSI 23
```

MicroSD ma służyć przede wszystkim jako:

* cache okładek,
* storage dodatkowych grafik,
* storage ikon,
* opcjonalny storage dodatkowych fontów,
* konfiguracja/cache,
* opcjonalne logi diagnostyczne.

## Ważne

SD nie zastępuje RAM ani PSRAM.

Aktualnie renderowana grafika nadal musi być obsługiwana przez RAM/decoder.

Jednak SD powinna znacząco zmniejszyć:

* potrzebę ponownego pobierania okładek,
* użycie Flash,
* ilość assets kompilowanych do firmware.

Firmware powinien działać także bez karty SD w trybie zdegradowanym.

Brak SD NIE może powodować bootloopa.

# 7. COVER CACHE

Mechanizm:

```text
Windows Media Session
        ↓
Windows Agent
        ↓
pobierz thumbnail
        ↓
crop do 1:1
        ↓
resize
        ↓
JPEG
        ↓
hash coveru
        ↓
ESP32 pyta:
czy mam ten hash na SD?
        ↓
TAK → load SD
NIE → HTTP download → SD → display
```

ESP32 nie powinno pobierać tego samego obrazu wielokrotnie.

Cache powinien mieć prosty limit.

Na początek:

```text
MAX COVER CACHE = 256 MB
```

Po przekroczeniu limitu usuwaj najstarsze / najdawniej używane pliki.

Nie skanuj całej karty SD przy każdym frame.

Metadata cache można trzymać osobno.

---

# 8. COVER ART FORMAT

Ciężką obróbkę wykonuje PC.

ESP32 ma dostawać już przygotowany obraz.

Zacznij od:

```text
resolution: 128×128 lub 140×140
format: JPEG
quality: około 80
square crop: TAK
```

Sprawdź oba rozmiary wizualnie.

Jeżeli 140×140 działa stabilnie, użyj 140×140.

Nie wysyłaj na ESP32:

* PNG 1000×1000,
* JPEG 2000×2000,
* Base64 z dużymi obrazami.

HTTP ma przesyłać binarny JPEG.

---

# 9. BRAK PSRAM — KRYTYCZNE

ESP32-2432S028R nie posiada PSRAM.

Projektuj pamięć od początku z tym ograniczeniem.

Dla RGB565:

```text
140 × 140 × 2
≈ 39 KB
```

Jedna rozpakowana okładka jest realna.

Kilka dużych bitmap jednocześnie już może być problemem.

NIE:

* trzymaj wielu coverów w RAM,
* używaj pełnego framebuffer 320×240 bez potrzeby,
* rób bezmyślnie podwójnych/trójnych buforów,
* alokuj dużych bitmap przy każdym frame,
* trzymaj jednocześnie starej i nowej okładki tylko dla crossfade,
* dekoduj ogromnych grafik.

Preferuj:

* małe LVGL draw buffers,
* streaming JPEG decode,
* line/block decoding,
* wielokrotne używanie tych samych buforów,
* stałe alokacje zamiast ciągłej fragmentacji heap,
* cache SD.

# 25. COVER HTTP

Przykład:

```text
GET /api/covers/{coverId}.jpg
```

ESP32:

1. otrzymuje `coverId`,
2. sprawdza SD,
3. jeśli plik istnieje → ładuje lokalnie,
4. jeśli nie → pobiera,
5. zapisuje na SD,
6. dekoduje,
7. wyświetla.

Pobieranie musi używać timeoutów.

Nie blokuj całego GUI podczas wolnego transferu.

# 26. DISCOVERY

Nie chcę wpisywać adresu IP komputera na stałe.

**mDNS**


* ostatni znany adres zapisany w NVS,

```text
last known host
↓
mDNS/discovery
↓
manual fallback
```

# 30. PAIRING FLOW

Przy pierwszym połączeniu:

```text
ESP32
↓
hello + deviceId
↓
Agent
↓
device pending approval
```

W lokalnym panelu Windows użytkownik widzi:

```text
New PC Dock detected

Device:
CYD-A81F

[ APPROVE ]
[ REJECT ]
```

Po zatwierdzeniu agent generuje silny losowy token.

Token zapisują:

* Windows Agent,
* ESP32 NVS.

Każde następne połączenie wymaga tokena.

Token powinien mieć odpowiednią entropię, np. losowe 256 bitów.
