> STATUS KRYTYCZNEJ ŚCIEŻKI USB (ZWERYFIKOWANE NA SPRZĘCIE): firmware cyd28_st7789_app wgrane na fizyczny CYD (ESP32-D0WD-V3 na COM5). Zdiagnozowano i usunięto błąd `IOException: The I/O operation has been aborted` (Win32 ERROR_OPERATION_ABORTED 995) w .NET SerialStream.ReadAsync na Windows przez wprowadzenie pollingu rejestru sprzętowego `BytesToRead` w `SerialPortUsbDuplexStream`. Usunięto zakłócenia linii DTR/RTS po otwarciu portu. Wydłużono probe timeout do 6.0s (start ST7789 z LVGL i Wi-Fi trwa 2.6s) oraz próg linii bootloadera do 25. Agent pomyślnie wykrywa CYD, łączy się jako `remoteAddress: "USB"` (hostStatus="connected"), odbiera pełną telemetrię urządzenia (WiFi, SD, heap, firmware) i przesyła ustawienia. Windows Agent działa w zasobniku systemowym (PID 18264).

> STATUS DISCOVERY AGENTA W FIRMWARE (częściowo): wcześniej udane mDNS nadpisywało `config_.port`, więc późniejszy fallback na `manualHost` mógł użyć portu poprzedniego Agenta. Teraz skonfigurowany port pozostaje niezmieniony, port mDNS dotyczy tylko odkrytego endpointu, a reklamowany port 0 nie jest akceptowany. Test hostowy selekcji endpointu PASS; ST7789 PlatformIO build SUCCESS (RAM 72684/327680, flash 1478861/2031616). Punkt discovery/reconnect weryfikowany w warstwie USB; mDNS/LAN discovery pozostaje AWAITING HARDWARE VERIFICATION.

> STATUS WEBSOCKET (częściowo): osobny test loopback na porcie efemerycznym (nie 8765) przeszedł przez hello CYD → pending → zatwierdzenie → pairing.token/hello/connected/device.settings → reconnect z bearerem bez echa tokenu po WebSocket. Test potwierdził ramkę Agent→device oraz ping/pong device→Agent; Windows Agent smoke PASS. Istniejący kod produkcyjny nie wymagał zmiany. Test nie weryfikuje fizycznego CYD, portu 8765, wielu interfejsów ani zapory na realnej sieci; te kryteria pozostają otwarte.
