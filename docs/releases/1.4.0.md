# CYD-DECK 1.4.0

CYD-DECK 1.4.0 delivers a streamlined first-boot onboarding flow on the ESP32 dock, a dedicated **Devices (`Urządzenia`)** management view in the Windows Agent, sub-50 ms page navigation via view caching, and a unified **`CYD-DECK.exe`** product identity across Windows shell surfaces, autostart, and installer packages.

---

## 1. Installation Methods

### A. Online Browser Web Installer (Recommended for CYD)
You do not need to install Python, PlatformIO, or extra tools:
1. Open the [CYD-DECK Web Installer](https://blankeuuu.github.io/cyd-deck/web-installer/) in **Google Chrome**, **Microsoft Edge**, or **Brave** on desktop.
2. Connect your **CYD ESP32-2432S028R** board to your PC using a micro-USB data cable.
3. Click **Install Firmware**, select the detected COM port (e.g., *CH340* or *CP2102*), and click **Connect**.
4. Flashing completes in ~30 seconds, after which the device automatically reboots into the CYD-DECK interface.

### B. Windows Agent Installer (`CYD-DECK-Setup-1.4.0-win-x64.exe`)
Download the installer from the GitHub Release.
- **Per-user installation**: Installs into `%LOCALAPPDATA%\Programs\CYD-DECK` without requiring administrator privileges.
- **Self-contained bundle**: Includes the .NET 10 runtime, SkiaSharp graphic dependencies, and all required libraries under the unified `CYD-DECK.exe` binary.
- **Safe upgrade & uninstallation**: Automatically migrates legacy `StreamDeckWindowsAgent` autostart entries while preserving CLI arguments, removes deprecated `StreamDeck.WindowsAgent.*` binaries/shortcuts, and cleanly terminates active background tray instances during setup or uninstallation.
- A portable package (**`CYD-DECK-win-x64.zip`**) is also available.

### C. Command Line Flashing via `esptool.py`
- **Application upgrade** (preserves NVS, Wi-Fi credentials, transport mode, and pairing):
  ```bash
  esptool.py --chip esp32 --port COM5 --baud 460800 write_flash -z 0x10000 firmware-ST7789-1.4.0.bin
  ```
- **Clean install on a new board** (from address `0x0`):
  ```bash
  esptool.py --chip esp32 --port COM5 --baud 460800 write_flash -z 0x0 firmware-ST7789-1.4.0-full.bin
  ```

## 2. Changelog

### CYD Firmware (ESP32 / LVGL 9.3)
- **Onboarding Transport Choice (USB-only vs Wi-Fi + USB)**:
  - After touch calibration on first boot, the device presents a clear transport selection screen allowing users to choose **USB Cable (No Wi-Fi)** or **Wi-Fi Network (SoftAP portal)**.
  - Selected transport mode (`connectionMode`) is persisted in NVS (`OnboardingStorageState`). Choosing USB-only immediately disables the Wi-Fi radio and skips SoftAP provisioning.
  - Users can switch transport modes at any time without a factory reset: re-open the Wi-Fi setup portal from **Settings (Gear) > Device > Connection & status > Wi-Fi setup** (`OpenSetupPortal`), or tap **Use USB instead (No Wi-Fi)** inside the portal screen to return to USB-only operation while keeping saved Wi-Fi credentials intact.

### Windows Agent
- **Dedicated Devices (`Urządzenia`) Sidebar View**:
  - Added a first-class **Devices** navigation tab in `SettingsWindow` built around three Apple HIG cards:
    1. **Pairing Requests (`Prośby o parowanie`)**: Displays pending USB or Wi-Fi pairing requests with device ID, firmware version, transport badge, setup key input (for Wi-Fi), and one-click Approve / Reject actions.
    2. **Active Connections (`Aktywne połączenia`)**: Live connection telemetry, transport status (USB COM port / Wi-Fi IP), and quick serial port selection.
    3. **Paired Devices (`Sparowane urządzenia`)**: Lists approved devices with creation/last-seen timestamps and one-click **Revoke (`Odwołaj`)** management.
  - Added an inline pending-pairing notification banner across the main window for immediate visibility regardless of the active tab.
- **Immediate USB & Wi-Fi Pairing Responsiveness**:
  - Pending USB and Wi-Fi pairing events immediately trigger UI state refreshes and surface the pairing dialog/banner without waiting for background timer ticks.
- **Manual COM Port Persistence**:
  - Manually selecting a specific `COMx` port (or `Auto`) is persisted to configuration and respected across reconnects and agent restarts.

### Performance
- **SettingsWindow Page View Cache**:
  - Cached constructed page subtrees (`Deck`, `Media`, `Monitor`, `Devices`, `Settings`) in `SettingsWindow` instead of rebuilding WinForms control hierarchies on every tab switch.
  - Warm `ShowPage` navigation latency dropped from ~97–221 ms to **p50 7–23 ms** (well within the `< 50 ms` responsiveness budget).
- **Rendering & Startup Optimizations**:
  - Eliminated per-row GDI `Region` allocations in `ShortcutLibraryRow` and removed duplicate `RebuildLibrary()` calls during deck initialization.
  - Cached the processor name read from Windows Registry (`Hardware\Description\System\CentralProcessor\0`) to avoid repeated synchronous registry queries during telemetry refreshes.

### Product Identity & Branding
- **Unified `CYD-DECK.exe` Executable & AUMID**:
  - Renamed the primary Windows Agent output assembly and executable from `StreamDeck.WindowsAgent.exe` to **`CYD-DECK.exe`** (`Product` and `AssemblyTitle` set to `CYD-DECK`).
  - Set explicit `AppUserModelID` (`Blankeuuu.CYD-DECK`) at process startup via `SetCurrentProcessExplicitAppUserModelID` and in Inno Setup Start Menu / Desktop shortcuts.
- **Safe Autostart Migration**:
  - `WindowsStartupService` and the Inno Setup installer safely migrate legacy `HKCU\...\Run\StreamDeckWindowsAgent` entries to `CYD-DECK` while preserving custom CLI arguments (such as `--usb-port COM5` or `--minimized`) and ignoring unrelated executables.
- **Official CYD-DECK Icon Assets**:
  - Added vector and raster master icons (`agent/assets/cyd-deck.svg`, `agent/assets/cyd-deck.png`) and a multi-frame Windows icon (`agent/assets/cyd-deck.ico` with 16, 24, 32, 48, 64, 128, and 256 px PNG frames) used consistently across the `.exe`, window chrome, tray icon, and setup wizard.
